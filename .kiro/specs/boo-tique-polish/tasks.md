# Tasks: Boo-tique Polish

Rules for every task:

- Each top-level task is executed in its own separate run. Do not start the next task in the same run. Read `requirements.md`, `design.md` and the steering files first; nothing else is needed.
- The only shell commands available are `npx vitest run <file> --maxWorkers=2` (one test file per command), `npx tsc --noEmit`, `npm run lint` only in task 10, and, only in task 10, one `npx vitest run tests/boo-tique --maxWorkers=2`. Everything else is denied: no `npm install`, no `npm run build`, no `npm run dev`, no watch mode, no command chaining, no redirection, no `echo`, `ls`, `cat` or `grep`. Use the file read, directory listing, search and write tools for file work.
- During a task, run only the test files the task lists, plus `npx tsc --noEmit` when types changed. Do not run the full suite or a production build. The owner runs each of them once at the end.
- Size cap per task: at most 3 test files and at most 4 source files. A source file is any non-test file created, edited or deleted: components, lib, app, CSS, JSON fixtures, research files and old-spec lines. Each task lists its test files and its source files by path. If a task seems to need more, stop and report instead of exceeding the cap.
- Write the test first, then the code that makes it pass (test-first). Tests contain no JSX; use `createElement`. When a listed test file contains an old assertion that the "Supersedes" table of `requirements.md` replaces, change that assertion to the new wording in the same step and do not weaken any other assertion.
- Add no dependency. If one seems needed, stop and report it.
- Do not edit files under `.kiro/specs/foundation/`, `.kiro/specs/foundation-fixes/` or `.kiro/specs/page-capture/`, and do not touch `.github/`, `.githooks/`, `scripts/`, `SECURITY.md` or `.kiro/agents/`. The only edits to `.kiro/specs/boo-tique-static/` are the two single lines of task 2. Do not read or write `.env` files.
- Do not edit `app/globals.css`, the root `app/layout.tsx` or `vitest.config.ts`. CSS changes go only into `app/boo-tique/boo-tique.css`, scoped by `.bt-` classes. The stylesheet has no `body`, `html` or `:root` selector, and the words `body` and `html` do not appear in it, even in a comment.
- Hex colour constants are lower case everywhere. No hex literal in a `.tsx` file: use `PALETTE`.
- No price string in a `.tsx` file: no `$` followed by a digit. Use `formatUsd` and the shared source `lib/boo-tique/cart.ts`.
- Every planted element carries `data-testid="<entry id>"` and nothing in the DOM names the pattern or the verdict. Any other test id starts with `bt-`. The three phase-2 flag elements carry no `data-` attribute other than `data-testid`. No class or id value contains `urgency`, `scarcity`, `activity`, `shaming`, `preselect`, `interference`, `sneak` or `drip`.
- Detectors, judges and the extractor never read `data-testid`.
- Honest look-alikes stay honest. Outside the 30 listed elements, no copy is manipulative. Add no "Selling fast" or other badge to a grid card. Shop copy avoids the word "target".
- Word rules are checked on visible text with the `visibleText` helper, never on raw markup, so test ids and attributes are not scanned.
- The only `"use client"` files allowed are `club-timer.tsx`, `cookie-banner.tsx`, `hero-countdown.tsx`, `overlay-dialog.tsx`, `sold-toast.tsx` and `toggle-switch.tsx` in `components/boo-tique/`.
- Overlay and switch behaviour (click, timer, focus) is not testable in node. Test only the pure helpers, the server markup, the stylesheet text and source scans.
- Do not edit `tests/boo-tique/coverage.test.ts`, `tests/boo-tique/helpers/pending-routes.ts` or `tests/boo-tique/helpers/route-table.ts`. `PENDING_ROUTES` stays empty.
- Planted inline-styled elements keep their exact inline styles from the old "Exact style values" table. `lib/boo-tique/styles.ts` is not edited. The classes `bt-button`, `bt-button--secondary` and `bt-button--quiet` are never applied to an element that has a `style` attribute.
