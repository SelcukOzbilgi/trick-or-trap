# Tasks: Boo-tique Static Pages

Rules for every task:

- Each top-level task is executed in its own separate run. Do not start the next task in the same run.
- The only shell commands available are `npx vitest run <file> --maxWorkers=2` (one test file), `npx tsc --noEmit`, and `npm run lint` only in task 13. Everything else is denied: no `npm install`, no `npm run build`, no `npm run dev`, no watch mode, no command chaining, no redirection, no `echo`, `ls`, `cat` or `grep`. Use the file read, directory listing, search and write tools for file work.
- During a task, run only the test file or files the task touched, plus `npx tsc --noEmit` when types changed. Do not run the full suite or a production build. The owner runs each of them once at the end.
- Write the test first, then the code that makes it pass (test-first). Tests contain no JSX; use `createElement`.
- Add no dependency. If one seems needed, stop and report it.
- Do not edit files under `.kiro/specs/foundation/` or `.kiro/specs/foundation-fixes/`. Do not read or write `.env` files.
- Do not edit `app/globals.css`, `app/layout.tsx` or `vitest.config.ts`.
- Hex colour constants are lower case everywhere.
- Every planted element carries `data-testid="<entry id>"` and nothing in the DOM names the pattern or the verdict. Any other test id starts with `bt-`.
- Honest look-alikes stay honest. Outside the 30 listed elements, no copy is manipulative (see "Honest look-alikes and the neutral copy rules" in `design.md`). Shop copy avoids the word "target".
- Word rules (insurance, handling, haunting, phone, real-brand names) are checked on visible text with the `visibleText` helper, never on raw markup, so test ids and attributes are not scanned.
- The only `"use client"` files allowed are `hero-countdown.tsx`, `sold-toast.tsx`, `club-timer.tsx`, `cookie-banner.tsx` and `overlay-dialog.tsx` in `components/boo-tique/`.
- Overlay behaviour (fixed positioning, focus, Escape, dismissal) is not testable in node. Test only the pure helpers, the server markup and the stylesheet text.
- `PENDING_ROUTES` (in `tests/boo-tique/helpers/pending-routes.ts`) lists the fixture routes whose page is not finished. A task that finishes a route removes it from `PENDING_ROUTES` and adds the page's `load` line to `ROUTE_TABLE` in the same step, then runs `tests/boo-tique/coverage.test.ts`. Until then, that page's own test renders it with `renderRoute(route, { table })` and a local one-entry table.
