# Tasks: Page Capture

Rules for every task:

- Each top-level task is executed in its own separate run. Do not start the next task in the same run. Read `requirements.md` and `design.md` of this spec at the start; the "Uses" line names what earlier tasks provide.
- The only shell commands available are `npx vitest run <file> --maxWorkers=2` (one test file), `npx tsc --noEmit`, `npm run lint` only in task 16, and in task 1 only the single `npm install --save-exact playwright-core@1.64.1 server-only@0.0.1`. Everything else is denied: no build, no dev server, no watch mode, no `@latest`, no command chaining, no redirection, no `echo`, `ls`, `cat` or `grep`. Use the file tools for file work.
- During a task, run only the test files the task touched, plus `npx tsc --noEmit` when types changed. Do not run the full suite. The owner runs it once at the end.
- Write the test first, then the code that makes it pass. Tests contain no JSX and no real network access.
- Any test file that imports a module which imports `server-only` starts with `vi.mock("server-only", () => ({}))`. Never edit `vitest.config.ts`.
- Add no dependency beyond task 1. If another seems needed, stop and report.
- `playwright-core` is imported only in `lib/capture/remote-browser.ts`, with `await import(...)` inside the connect function. No test imports it.
- The library never calls `console.*`. Tests use sentinel strings as secrets (for example `"sk-test-sentinel"`), never real values.
- Never read or write `.env` files. Only task 4 edits `.env.example`. Only task 1 edits `package.json` (and it is the only task that may run the install command). Only task 2 edits `next.config.ts`. Only task 5 edits `lib/types/index.ts`. Only task 16 edits steering files.
- Do not edit `app/globals.css`, `app/layout.tsx`, any other spec under `.kiro/specs/`, or anything in `.kiro/agents`, `.kiro/hooks` or `.kiro/settings`.
- Never run `tests/capture/remote-capture.test.ts`. No test starts a dev server or opens a connection.
- Use the file and function names of `design.md` exactly. Tests import with the `@/` alias.
