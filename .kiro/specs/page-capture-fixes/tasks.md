# Tasks: Page Capture Fixes

Rules for every task:

- Each top-level task is executed in its own separate run. Do not start the next task in the same run. Read `requirements.md` and `design.md` of this spec at the start, and look at the files the task names. Earlier tasks are done; the "Uses" text names what they provide.
- The only shell commands available are `npx vitest run <one test file> --maxWorkers=2`, `npx tsc --noEmit`, `npm run typecheck`, `npm run lint` (task 14 only), and in task 1 only the single `npm install --save-dev --save-exact jsdom@31.0.1`. Everything else is denied: no build, no dev server, no watch mode, no `@latest`, no command chaining, no redirection. Use the file tools for file work.
- During a task, run only the test files the task touched, plus `npx tsc --noEmit` when types changed. Do not run the full suite. The owner runs it once at the end. Never run `tests/capture/remote-capture.test.ts`.
- Write the test first, then the code that makes it pass. Tests contain no JSX and no real network access. Any test file that imports a module which imports `server-only` starts with `vi.mock("server-only", () => ({}))`. Never edit `vitest.config.ts`.
- Add no dependency beyond task 1. Only task 1 edits `package.json`. `playwright-core` stays imported only in `lib/capture/remote-browser.ts`, with `await import(...)` inside the connect function. No test imports it. No file under `lib/` imports `jsdom`.
- Never write the name of the test-id attribute (the HTML attribute whose name is "data-" plus "test" plus "id") in any file under `lib/capture`, and write "the test-id attribute" in comments, specs and messages. A guard test on the main branch fails on that word, in any case, under `lib/capture`, `lib/detectors` and `lib/judge`. Tests build the name from parts through `tests/capture/helpers/forbidden-attribute.ts` (created in task 2).
- Never read or write `.env` files. Only task 6 edits `.env.example`. Do not touch `.github/`, `.githooks/`, `scripts/`, `SECURITY.md`, `.kiro/agents/`, `app/`, or any spec other than the ones a task names.
- Use the names of `design.md` exactly. Tests import with the `@/` alias. The library never calls `console.*`. Tests use sentinel strings as secrets, never real values.
